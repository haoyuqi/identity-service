# Agent guide

Read the [architecture and feature map](docs/architecture.md) before changing
application behavior, and verify its paths against the source. Follow the
[code style](docs/code-style.md) and the development, verification, and review
rules in [Contributing](CONTRIBUTING.md).

Follow the [branch and commit conventions](CONTRIBUTING.md#branches-and-commits)
when preparing changes for review.

Update the owning documentation when implemented responsibilities, interfaces,
execution paths, data behavior, or failure handling change. Describe current
behavior; keep proposals in issues or pull requests. Do not add credentials,
demo accounts, or personal environment details to the public repository.
